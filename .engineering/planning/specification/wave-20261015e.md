## Wave 20261015e: M1 command line and the M2 specification, up to four units at once

Proposed 2026-10-15 at main `8a9be4e`, `aep:implementing` wave mode (skill 0.22.11). Operator asked for
up to four agents in parallel. Wave 20261015d is still closing (`story:m1-eventlog-store`).

## Why at most two units can start now

`aep plan artifact waves --kind story --status draft` orders the backlog as a chain at the front:
wave 1 `m1-cli-sample`; wave 2 `m1-cli-eval-show`, `m2-compare`; wave 3 `m2-scheduler`,
`m2-spec-history-records`; wave 4 `m2-auto-unmute`, `m2-hysteresis-core`, `m2-store-baselines`, … .
`m1-cli-sample` waits on `m1-eventlog-store` (wave 20261015d). Every other ready story waits on
`m1-cli-sample`, `m1-cli-eval-show` or `m2-spec-history-records`.

`story:m2-spec-history-records` depends on `story:m1-cli-eval-show` only for ordering ("it
regenerates `generated/` … which every M1 story compiles against"); it shares no file with the M1
command-line stories. Proposed: remove that `depends_on` edge, so the specification story runs now and
its successors (`m2-hysteresis-core`, `m3-vocabulary-mapping`, `m4-design-record`) can start while
the command line is built. A merge that meets regenerated output reruns `task generate`.

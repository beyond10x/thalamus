## Outcome

The specification and every generated file follow the newest ESS release, 0.60.0, as the workspace
rule requires ("always upgrade to most recent ESS"). On 2026-10-15 `ess --version` on the
development machine printed `ess 0.60.0` while `spec/ess-inputs.yaml` pinned `requires: ess 0.59.0`,
so the docs generator, which runs `ess` from the repository root, was refused by `--strict-requires`.

## Work

- `spec/ess-inputs.yaml`: `requires: ess 0.60.0`; move `format:` to the newest the release
  implements (`ess specify formats --since ess/24`) only if nothing else changes with it.
- `task generate`; commit the regenerated `generated/` and `spec/suite.json`.
- `.github/workflows/check.yml`: `ESS_VERSION` 0.60.0 with its SHA256SUMS line.
- Fix whatever the regenerated model changes in the crates.

## Acceptance

- `task check` (plain `ess` on `PATH`, no `ESS=` override) exits 0.
- `grep -n 'requires: ess 0.60.0' spec/ess-inputs.yaml` prints one line.
- The first `Check` run on GitHub after the merge concludes `success`.

## Context

`epic:web-ui` Ships, the last of its own checks: "an end-to-end check that the built page renders a fixture instance's data from a running service". Running code is Rust, so the check is a Rust test; no Node test runner and no browser-automation package drives the page (`story:m6-design-record` items 1 and 6). The browser is a disposable headless Chromium container pinned by digest, started by `task test-web-e2e` the way `task test-postgres` starts PostgreSQL, or the one `THALAMUS_TEST_CHROME_URL` names. The test sits behind the cargo feature `web-e2e` that `story:m6-web-skeleton` declares, so `cargo test --workspace` in `task test` does not need a browser, and `task check` runs it through `task test-web-e2e`.

It lands after the three views it checks (`depends_on`). It is also where the capability is announced: the status item and the concepts page.

## Work

- `crates/thalamus-service/Cargo.toml` (after `story:m6-web-skeleton`): one DevTools-protocol client under `[dev-dependencies]` that connects to a running browser over its websocket and downloads nothing at build time; `[[test]] web_e2e` with `required-features = ["web-e2e"]`. `Cargo.lock` is regenerated by the coordinator at merge.
- `crates/thalamus-service/tests/fixtures/web_instance/` (new): a fixture instance with no organization-specific name: signals in two families, series whose newest verdicts are `OK`, `WARN`, `UNKNOWN` and `N/A`, one settled transition; seeded into a SQLite store at test start; no source reachable.
- `crates/thalamus-service/tests/web_e2e.rs` (new): serves the fixture store with `http::serve` on `127.0.0.1:0`, connects to the browser, opens `/ui/`, waits for the views to render and reads the DOM; publishes one evaluation into the broadcast while the flow view is open; records every network request the page makes.
- `Taskfile.yml`: `test-web-e2e` (the shape of `test-postgres`: `THALAMUS_TEST_CHROME_URL` when set, otherwise a container pinned by digest on the host network, removed on exit; then `cargo test --locked -p thalamus-service --features web-e2e --test web_e2e` and clippy over the same target with `-D warnings`); `check` calls it after `test`.
- `crates/thalamus-docs/src/status.rs`: a `shipped` item for the web UI whose evidence is `crates/thalamus-service/tests/web_e2e.rs::built_page_renders_the_board_from_the_fixture_instance`; then `task docs-generate` (`website/data/status.json`).
- `website/docs/concepts/interfaces.md`: a section on the web UI: `/ui/`, the three views, read-only, served on the loopback listener of D31 and D43.

## Decisions taken here (decomposer calls, reversible)

- The browser is a container, not a requirement on the developer machine, following `task test-postgres`; CI runs the same task.
- The page is checked against the network log as well as the DOM, so "no CDN or any network fetch other than the serving `thalamus-service`" (epic, Not in scope) is a test, not only a header.

## Acceptance

`task test-web-e2e` passes, against the built page served from the fixture instance, the failing-first tests `built_page_renders_the_board_from_the_fixture_instance` (every seeded series with its verdict, no score text on the `UNKNOWN` and `N/A` rows), `series_view_renders_samples_evaluations_and_the_transition`, `flow_view_shows_an_evaluation_published_while_open` (its sample, the evaluation and its transition, in that order) and `page_requests_only_the_serving_origin`, and `task check` runs it and exits 0.

The docs follow (revised after review-result:m6-acceptance-round-1): `grep -nE "/ui/" website/docs/concepts/interfaces.md` prints a line of a web UI section that names the signal board, the series view and the flow view and states that the UI is read-only and served on the loopback listener (D31, D43); and the status item of the web UI is `shipped` with this story's e2e test as its evidence (`cargo test -p thalamus-docs` passes).

## Context

M4 of `docs/design/thalamus.md` § 9 adds views served by `thalamus-service` (§ 6.5), an HTTP API and a server-sent-events stream of evaluations (§ 5.1), deploy instants (§ 6.5) and the dashboard and rule export (§ 6.5, § 7). `story:m0-workspace` laid every module of M0 to M3 up front so that stories add code to their own files and never edit a shared module line. This story does the same for M4: it is the prefactoring every other `m4-` code story depends on. It lands after `story:m2-scheduler`, which owns `crates/thalamus-service/src/main.rs` and `crates/thalamus-service/Cargo.toml`, and after `story:m1-eventlog-store`, whose store handle the HTTP state holds.

## Work

- `crates/thalamus-service/src/main.rs` (owned by `story:m2-scheduler`; this story adds one option and one call): `thalamus-service run --instance <dir> [--listen <addr>] [--allow-remote]`. Without `--listen` no HTTP is served, exactly as in M2. With it, `http::serve` runs on its own thread with its own tokio runtime beside the scheduler.
- `crates/thalamus-service/Cargo.toml` (owned by `story:m2-scheduler`), every M4 change to it, once:
  - `[dependencies]`: `axum`, `tokio` (rt-multi-thread, net, sync, macros), `tokio-stream`.
  - `[dev-dependencies]`: `tower` (feature `util`) and `http-body-util`. These are the HTTP test dev-dependencies of every M4 view and API story and of `story:m5-service-answers`; no later story edits this file for tests. No network client is added.
  - `Cargo.lock` is regenerated by the coordinator at merge.
- The HTTP test technique, named here once: a test builds the router with `http::router(state)` over a seeded store, sends an in-process request with `tower::ServiceExt::oneshot`, and reads the body with `http_body_util::BodyExt` (`collect` for a whole body, `frame` for the SSE stream). No socket is bound and no network client is used. `story:m4-service-api`, `story:m4-heatmap`, `story:m4-live`, `story:m4-sparklines`, `story:m4-week-vs-week` and `story:m4-before-after` use it and add no dev-dependency.
- `crates/thalamus-service/src/lib.rs`: module lines `http`, `api`, `live`, `views`.
- `crates/thalamus-service/src/http.rs` (complete here, owned by this story): the shared state `AppState` (instance directory, a read handle on the instance store, the `tokio::sync::broadcast` sender of recorded evaluations, the live table handle), `pub fn router(AppState) -> axum::Router`, `serve`, and the M4 route table: `GET /` (an index linking every view), `GET /api/verdicts` and `GET /api/series` (`api.rs`), `GET /api/evaluations/stream` and `GET /views/live` (`live.rs`), `GET /views/heatmap`, `GET /views/sparklines`, `GET /views/week`, `GET /views/deploys` and `GET /views/deploys/{id}` (`views/*.rs`). ## Decisions taken here (decomposer call, reversible)

- Views live in `thalamus-service` (`src/views/`), the dashboard and rule export in `thalamus-core` (`src/export/`, pure: definitions in, text out). No new crate, so the root `Cargo.toml` `members` line is untouched and design § 5.1 keeps its crate table; `story:m4-design-record` adds the CLI and service lines.
- HTML and SVG are rendered by Rust; no Node build and no `<script>` element (the workspace rule that running code is Rust). The live view therefore refreshes the page instead of running a browser script (`story:m4-live`).
- `--listen` binds a loopback address only unless `--allow-remote` is given; there is no authentication in M4 (design § 10 question 2: the service runs per operator machine).
- HTTP tests run in process through `tower::ServiceExt::oneshot` (coordinator decision C5, round 1): no port, no client crate, and one dev-dependency edit for the whole milestone.

- `cargo run -q -p thalamus-cli -- --help` lists `export` and `deploys`; `cargo run -q -p thalamus-cli -- export` and `-- deploys` each exit 70 printing `not implemented`.
- `cargo test -p thalamus-service --test http` passes the failing-first tests `no_listen_serves_no_http`, `index_links_every_view_route`, `unknown_route_answers_404`, `post_to_any_route_answers_405` and `remote_listen_address_refused_without_allow_remote`, the route tests through `http::router` and `tower::ServiceExt::oneshot` with no socket bound.

## Decisions taken here (decomposer calls, reversible)

`story:m5-design-record` writes each of these into design § 11.

- An `errored` case (the instrument failed) maps to a sample of quality `unknown`; a `failed` case (a defect) to value 0; a `skipped` case records no sample (design § 6.3 names only the first two).
- `test.run.pass_ratio` = passed / (passed + failed + errored) over the counts `RunFinished` carries; with any errored case the reading is `partial` with bound `upper` at (passed + errored) / that total, so it may escalate and never clear (design § 3.1 rule 4); with no gradable case it is `unknown`.
- A test-run definition names `source: {adapter: testrun, connection: <the CloudEvents source it accepts>}`; the connection is a label, not a Connectors connection, because test-run events are pushed, not read.
- A rollup record cites its rollup and series, not an evaluation: a D14 rollup counts many evaluations and outlives them. A definition record cites its file digest and revision. Only a transition record cites evaluations (all `k`, plus the settling one copied).

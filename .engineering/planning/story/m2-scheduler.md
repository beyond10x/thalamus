## Context

Lesson L7 (design § 1): "two history series were started and abandoned; the one that survived was written by a step that always ran". Design § 5.3 gives the cadence to the scheduler of the service, not to whoever remembers. M2 ships the scheduler in `thalamus-service`. Each slot runs the read → sample → grade → evaluate pass of the library crate `thalamus-pipeline` that `story:m1-cli-sample` and `story:m1-cli-eval-show` wrote (`depends_on story:m1-cli-eval-show`); the scheduler adds no pass of its own. The crate, its `lib.rs` module lines and its `members` line are `story:m0-workspace`'s.

`crates/thalamus-service/src/scheduler.rs` is owned by this story. Three later stories each put their logic in their own file and add one hook line here, in this order (`depends_on` chain): `story:m2-auto-unmute` (the expiry check before sampling), then `story:m2-rollup` (the closed-day rollup after each UTC midnight), then `story:m2-transitions` (the settled-change hook after grading). The hooks are calls, so each is a single line in the tick.

## Work

- `crates/thalamus-service/src/main.rs` (clap derive): `thalamus-service run --instance <dir>`.
- `crates/thalamus-service/src/scheduler.rs`: slots are multiples of the cadence of a definition from the Unix epoch, UTC. At each slot every definition in `thalamus.definition.ActiveDefinitions` (`spec/domains/definition.yaml:762`) goes through one pipeline pass: read through the extractor registry, `RecordSample`, grading and `RecordEvaluation`. One `run_id` per pass (`thalamus.observation.Provenance`).
- Definitions are re-read every tick, so an activation, revision, mute or retirement takes effect at the next slot. `Proposed`, `Muted` and `Retired` definitions are not sampled, except a `Muted` definition whose expiry has passed, which `story:m2-auto-unmute` hands back as `Active` (design § 11 D19).
- A read that has not finished within the cadence is recorded as `quality: unknown` with reason `read timed out` (design § 2.2), never as 0.
- A missed slot (service down, clock jump) is never re-read from the source and never interpolated. It is recorded (design § 11 D16): on start, and after a clock jump, every slot of an `Active` definition since its newest stored sample gets one sample per series of that definition's newest pass, with quality `unknown` and reason `missed_slot`; the current slot is then sampled, and only if no sample of it exists.
- `crates/thalamus-service/Cargo.toml`: the dependencies of the service (`Cargo.lock` is regenerated by the coordinator at merge).
- Clock and adapter are injected traits, so the tests run with no source.
- Not here: HTTP API and event stream (later milestones), the daily rollup (`story:m2-rollup`), the expiry handling (`story:m2-auto-unmute`), transitions (`story:m2-transitions`).

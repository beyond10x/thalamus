# AGENTS.md — thalamus

Instructions for agents changing this repository. Humans start at [README.md](README.md); the
design is [docs/design/thalamus.md](docs/design/thalamus.md).

## What this is

Thalamus samples signals from the systems an organization runs, grades each sample into a verdict
(`OK`, `N/A`, `WARN`, `CRIT`, `UNKNOWN`) against a baseline, and serves the live verdicts,
history, assertions and events. Cortex is its long-term memory; conductor is its first consumer.

| path | holds |
|---|---|
| `docs/design/` | the design; read it before planning or code |
| `.engineering/` | the AEP planning store |
| `assets/` | the logo |
| `spec/` | the ESS specification, the source of truth for the model |
| `generated/` | code and the conformance suite generated from `spec/`; never edited by hand |
| `crates/` | the Cargo workspace |

Crates (design § 5.1): `thalamus-core`, `thalamus-store`, `thalamus-sources`, `thalamus-pipeline`,
`thalamus-service` and `thalamus-cli` (binary `thalamus`), over the generated `thalamus-model`.

## Commands

| command | does |
|---|---|
| `task check` | the gate: spec validity, generated-code drift, fmt, clippy (`-D warnings`), every test, documentation drift |
| `task generate` | regenerate `generated/` and `spec/suite.json` from `spec/` |
| `task drift` | fail when `generated/` or `spec/suite.json` differ from what `spec/` generates |
| `task build`, `task test` | release build; every test of the workspace |
| `task docs-generate` | regenerate the site's derived files under `website/` (`thalamus-docs generate`) |
| `task docs-check` | fail when a derived site file is missing, stale or hand-edited, or a status claim lost its test or planning artifact |
| `task website` | build the documentation site as CI does (`npm ci`, `npm run build` in `website/`) |
| `aep plan artifact validate` | validate the planning store |

- Every cargo call is `--locked`; `Cargo.lock` is committed.
- Format with `cargo fmt -p <crate>`. `cargo fmt --all` also formats the generated crates, which
  are path dependencies, and rewrites them.
- A story that implements a `thalamus` subcommand removes it from `STUBS` in
  `crates/thalamus-cli/tests/adv_stub_exit.rs`, which holds every stub to exit 70.
- `thalamus-core` dev-depends on itself with feature `conformance`, so its integration tests and
  the clippy step compile `thalamus_core::conformance`.

## Order of work

1. ESS first: every noun (`SignalDefinition`, `SignalSample`, `SignalEvaluation`,
   `DimensionRegistry`, `Assertion`) is specified under `spec/` before a story that uses it is
   implemented. A story's acceptance is a set of named conformance scenarios.
2. The AEP planning store is the plan. Work is recorded there, never only in a chat or a file.

## Documentation site

The site at <https://beyond10x.github.io/thalamus/> follows the independent project-site pattern of
cortex, canon and loom: Docusaurus under `website/`, with `@beyond10x/docs-system` pinned by commit
in `website/package.json`, built here and published by the organisation's reusable workflow. Node
is used for the site build only; everything derivable is generated by the Rust crate
`crates/thalamus-docs`.

- **Generated, never hand-edited** (`thalamus-docs generate`, run by `task docs-generate`):
  `website/docs/reference/ess/` (from `ess generate --kind docs`), `website/data/ess/` (one domain
  graph per domain and `thalamus.domain-graph.json` for the whole model, from `ess specify
  compile`), `website/static/schemas/` (one JSON Schema per entity, from `ess generate --kind
  schema`), `website/data/status.json` (from `CAPABILITIES` in
  `crates/thalamus-docs/src/status.rs`) and `website/static/img/logo.svg` (from `assets/logo.svg`).
  `task docs-check`, the last step of `task check`, fails when any of them drifts.
- **Status claims:** `shipped` means code on `main` and names its evidence, a test as
  `path::function` or a `Taskfile.yml` task; `planned` names its `story:` or `epic:` artifact.
  Generation fails when either does not exist
  (`crates/thalamus-docs/src/status.rs::shipped_items_need_a_test_or_task_that_exists`,
  `crates/thalamus-docs/src/status.rs::planned_items_need_a_planning_artifact_that_exists_and_carry_no_evidence`)
  and warns when a
  planned item's story is `implemented`. A story that ships a capability moves its item to
  `shipped` in `status.rs` in the same change, then `task docs-generate`.
- **Hand-written:** every other page under `website/docs/`, and the landing page
  `website/product.json`. Every claim must be checkable against the code, `spec/`, the design or
  the planning store. When a change alters behaviour a page describes, update the page in the same
  change; a page that describes unbuilt behaviour carries a `:::caution[Planned]` admonition.
- **Admonitions** carry their title in brackets (`:::caution[Planned]`); `thalamus-docs` refuses a
  raw title.
- **Publication:** `.github/workflows/pages.yml` ("Documentation validation") builds the site on
  every pull request and push, and on a push to `main` binds it to its commit
  (`thalamus-docs provenance` writes `.well-known/b10x-site.json`) and uploads it.
  `.github/workflows/b10x-docs-site.yml` ("Documentation site") hands that artifact to
  `beyond10x/website/.github/workflows/project-site.yml`, which deploys it to GitHub Pages at
  `/thalamus/`; it runs only for bot-authored commits on `main`. Actions and the reusable workflow
  are pinned by commit SHA, at cortex's pins.
- npm 12 refuses Git dependencies by default; `task website` passes `--allow-git=root` for the
  pinned `@beyond10x/docs-system`. CI's Node 22 does not need it.
- `website/build`, `website/node_modules` and `website/.docusaurus` are build output; they are
  ignored and never committed.

## Hard rules

- **Committed code is Rust**, command lines with clap derive.
- **No secret enters thalamus.** A source names a Connectors connection id.
- **Read-only against watched systems.** Thalamus never writes to a source.
- **Unknown is never 0 and never OK.** `quality: unknown` carries no value (the `Reading` union); keep it a type-level
  rule, not a convention.
- **One copy of every threshold**, in its definition.
- **No instance data in Git**, and nothing organization-specific: no company, customer, product or
  host names in code, docs, examples, tests or the planning store. The repository is public.
- **Every commit and GitHub write goes through the bot** (`b10x-gates bot`, `b10x-gates api`), after
  `b10x-gates scan-text` on every staged file.
- **Nothing outlives the session that started it.** Agents create no background process that
  keeps running after their session ends: no systemd units or timers, no cron entries, no
  containers with a restart policy (`restart=unless-stopped`, `always`), no detached or `nohup`
  servers. Sessions forget what they started: a sampling timer left running every minute grew
  from 3.5 s CPU and 110 MB to 2 min 40 s and 3.5 GB per run and kept a core busy overnight. A
  long-running process exists only when the operator asks for it, and then it is listed in the
  table below with its stop command, in the same change that starts it.

  | process | started by | stop command |
  |---|---|---|
  | (none) | | |
